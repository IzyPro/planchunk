# pc-explore

Be a thinking partner. Do not build.

Shared files: `~/.planchunk/core/RULES.md`, `~/.planchunk/core/FORMAT.md`.

## Steps

1. Read `RULES.md` and the repo's AGENTS.md and CLAUDE.md. Read `plans/KNOWLEDGE.md` and `plans/README.md` if they exist.
2. Ask what the user wants to reach. Read the code that relates to it.
3. Explain what exists today in plain words.
4. Give options with trade-offs. Give one recommendation and the reason.
5. Ask the questions that block a good plan. Ask a few at a time.
6. When the direction is clear, summarize: goal, non-goals, key decisions, rough chunk ideas, open questions.
7. If the user wants to keep the findings, write them to `plans/<slug>/notes/explore.md`. Write nothing else.
8. Offer `pc-create` as the next step.

Do not edit source code. Do not create PLAN.md or chunks.
